An `obs-fold` is an obsolete folded header line: an old server splits one header value over two lines, continuing it on the next line after a line break (CRLF) plus whitespace. The change joins those split lines back together right after the response is parsed, before any other code reads the headers. It has to happen this early because every consumer downstream reads the already-parsed values and would otherwise each see the raw split. A regex called `_OBSOLETE_FOLD_RE` finds each split in three steps: first optional spaces or tabs, then the line break itself, then at least one space or tab starting the continuation. The function `_normalize_header_value` swaps each match it finds for a single space, so `a=1` followed by a fold and `path=/` becomes the one value `a=1 path=/`. [[diff:src-urllib3-connection.py:80-88]]

The function `_normalize_header_values` repeats this for every header on Python's own header object, the `HTTPMessage`, in the order the headers arrived. For each value it checks whether unfolding changed anything; when it did, it deletes the headers from that object and adds the cleaned ones back in the same order, so nothing is lost and nothing moves. That way the `HTTPMessage` and urllib3's `HTTPHeaderDict` hold the same clean values instead of disagreeing about what the server sent. The function returns the cleaned headers, and `getresponse` builds the `HTTPHeaderDict` from them, so cookie consumers such as Requests never see the raw split.
