# Q6 (where) — source B

`SSLContext.load_ech_keys(keyfile, password=None, *, for_retry=True)` is server-side only: `Modules/_ssl.c:5423-5426` defines the signature.

* Role check: rejects `PROTOCOL_TLS_CLIENT` with `Cannot load ECH keys into a PROTOCOL_TLS_CLIENT context` (`Modules/_ssl.c:5443-5446`); `PROTOCOL_TLS_SERVER` and generic `PROTOCOL_TLS` are allowed. Docs state `Raises SSLError if the context uses PROTOCOL_TLS_CLIENT` (`Doc/library/ssl.rst:1834`).
* File format: `The file must contain a private key followed by its ECHConfigList` (`Modules/_ssl.c:5430`). Path is converted with `PyUnicode_FSConverter` (`Modules/_ssl.c:5452`), opened with `BIO_new_file(filename,"rb")` under `tstate_mutex` with threads released (`Modules/_ssl.c:5468-5477`).
* `for_retry`: passed to `OSSL_ECHSTORE_set1_key_and_read_pem(store,key,bio,for_retry)` (`Modules/_ssl.c:5402-5404`). Documented as `If for_retry is true, the new configurations are included in ECH retry configurations sent to clients` (`Doc/library/ssl.rst:1830-1832`) and `advertise the configurations in ECH retry responses` (`Modules/_ssl.c:5434-5435`). Each call appends to existing store (`Doc/library/ssl.rst:1830-1831`).
* Encrypted keys: `password` may be callable (`pw_info.callable=password`, `Modules/_ssl.c:5456-5457`) or string/bytes via `_pwinfo_set` (`Modules/_ssl.c:5458-5459`); only needed for encrypted keys (`Modules/_ssl.c:5431-5433`). Key is read with `PEM_read_bio_PrivateKey(...,_password_callback,pw_info)` (`Modules/_ssl.c:5387-5388`). Callback failure propagates (`Modules/_ssl.c:5483-5485`); tested with `ech-encrypted.pem` (`Lib/test/test_ssl.py:2363-2369`).
* Duplicate: existing store is fetched with `SSL_CTX_get1_echstore` or created new (`Modules/_ssl.c:5392-5400`); key counts compared before/after (`Modules/_ssl.c:5402-5404`). If `new_keys <= old_keys`, raises `SSL_R_PRIVATE_KEY_MISMATCH` (`Modules/_ssl.c:5408-5410`) per `We want to require a new match` (`Modules/_ssl.c:5407`), surfacing as `SSLError` via `_setSSLError` (`Modules/_ssl.c:5492`).
